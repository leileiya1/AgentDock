## 契约与可维护性选择

- 新模式显式启用；旧 TaskDetail/sidecar 角色协议不被伪装扩展。旧任务不生成虚构的团队项、语义覆盖核对或验收证据。
- `agent_runs` 仍是执行状态权威，团队上下文补充工作/成员/规范/输入/代次；工作项局部接受与候选最终验收不同。
- 内置 Claude Code/Codex 通过既有 DevelopmentResult 外壳传输；外壳 `revision=1`（旧 schema 最小值），`notes` 为 team-v1 JSON，回显完整团队身份。真实运行发现并修复了早期 `revision=0` 与旧 schema 的矛盾；没有放宽旧 schema。
- 计划是有版本 DAG；产品返工保留原验收契约，增加有审计历史的工作规范修复指令、输入和代次，不清零预算/返工。改变依赖/分工走显式局部计划修订。
- 每个写入尝试从精确基线、依赖增量或失败候选准备独立 worktree。集成按依赖顺序应用增量，记录已包含的产物，避免重复应用前置提交。
- 冲突先封存已集成内容，定向返工基于该候选；其他成员的有效成果保留。
- 测试成员选择验收契约中的具体 check ID，后端 Runner 实际执行 argv、校验退出码/输出并归档。没有执行的条目保持未测；只读审查不能代替实测。
- 只提供程序规则证据 `runner_rule`，没有把文本观测伪装成确定性断言。实际通道为命令 Runner，可运行本地 HTTP/浏览器测试程序；本轮未提供内置交互浏览器会话管理。
- 原始证据加密保存，按 task+evidence ID 读取并核对内容摘要，前端可查看脱敏原始输出。
- 本轮预算硬约束是受管尝试次数和单次时长；验证次数预留原子执行。未知 Token/费用保持未知。全局硬费用策略无法保证时阻断，不能显示虚假的硬费用保证。
- 项目设置、CLI 配置和团队策略保存快照；项目配置内容漂移会阻断派发并使最终证据失效。需要扩大授权/修改目标或验收契约时重新建立明确策略，不自动降低标准。
- 跨厂商审查考虑所有实际源码贡献者，包括后备开发者与冲突修复者。敏感路径沿用原完整性门禁和至少两位不同厂商的独立审查要求；当前两个内置厂商可能无法满足，必须阻断。
- CLI 内部分派被禁用（Codex multi_agent、Claude Agent/Task/Team 工具）。路径范围包含后端改动检查；CLI 自带沙箱和命令前缀授权不等于完整 OS 容器隔离。授权 `node` 等前缀包含运行相应脚本的能力。
- 合并复用既有批准封印/本地交付状态，同时用目标 ref CAS 防止把旧证据交付到已变化分支；团队仅开放本地交付，不开放 PR/MR。响应未知先查真实 tree/ref，保留操作意图，不重复创建副作用。
- 未知旧进程保留席位/资源并隔离目录；租约超时或单个父进程退出不能直接释放。未知副作用需对账，不会按普通故障盲目重试。

## 使用

```sh
cd /Users/sapiece/innovationProject/AgentDock-main/apps/desktop
bun run prepare:sidecar
bun run app:dev
```

1. 导入本地 Git 项目（不支持普通文件夹，不会替用户初始化 Git）。
2. 新建任务 → 切换到多 Agent 团队执行。
3. 填写原始目标、每行一条必须要求，设置成员角色、独立主规划、Provider 链、人数/并发和写入/命令范围。
4. 同 CLI 多实例需同时满足团队并发和设置中的 Provider/账号并发额度；默认 Provider 并发为 1，需要用户明确配置为 2 才会真正并行。
5. 可确认计划后运行，也可在已授权范围内自动推进。查看未测/失败/环境阻塞/失效证据，原始输出经后端摘要校验后打开。
6. 控制区可取消/恢复单项、在席位空闲后换绑、提交局部计划。目标分支变化时更新基线并重新集成/核对/实测/审查。若检查脚本本身有错，必须用“显式批准验收契约修订”说明理由并提交完整新清单，保留源码和累计额度，重新验收；模型不能静默降低验收。
7. 门禁通过才显示“已验收·待交付”；点击批准并本地交付后，真实内容对账通过才显示已交付。

### 实际运行发现后的修正

- 真实样本 04 的测试成员指出“逐字节不变”检查使用 `trim()`，后端拒绝让该提案进入开发。修复“已排入修正规划却被总状态误置为 BLOCKED”的推进问题，并补上受控回归。
- 修正后的流程从同一任务检查点继续，保留全部尝试和预算。未被覆盖核对接受的验收提案可按原始要求修正；已有有效覆盖、产物或候选后的契约仍受保护。
- 重新登录后的 Claude 曾返回额度/速率限制，后备 GPT 参与修正规划；没有把后备规划者算作源码贡献者，也没有放宽后续跨厂商审查。
- 成功的运行探针按实际 CLI 路径、版本和认证方式缓存；失败仍有界重试并退避，减少无用探针调用。
- `team_export` 示例可将后端事实和经摘要校验、脱敏的原始证据导出到新目录，便于审阅和续接。

### 后续补强与最终核对

- CLI 的环境局限使用 `environmentNotes` 单独上报；不再混入产品缺陷，也不能拿它代替后端 Runner 的证据。未认可的产品问题仍阻断。
- 内联 JS 语法错误和端口占用/监听权限失败归为阻塞，避免误消耗产品返工。明确期望的退出/输出仍优先按断言判断。
- 一个工作项阻塞时，无关且依赖已满足的工作仍可推进。敏感变更/审查委员会保持严格跨厂商规则及配置的审查 Provider 白名单。
- 复用既有通知：计划待确认、阻塞、待交付及完成时通知；相同 phase/detail 不重复生成事件或通知。OS 实际通知可见性受系统通知设置影响。
- Finder 的短 PATH 环境原本误报本机 CLI 未安装。补充标准用户目录和 Homebrew 路径发现；实际受限 PATH 检查可识别 Node、Bun、Codex 与 Claude 安装。Claude 钥匙串登录依赖正常用户会话/USER，未把“无会话”伪装已认证。
