# AgentFlow 像素小屋落地方案

依据：Claude Design 画布「C 像素小屋」页（C4 像素小样、C5 完整小屋）。本文定义把小屋从设计稿接进桌面端的分层、数据和阶段，先做可测试的基础设施，再接画面。

## 目标与铁律

- 小屋是任务状态的另一种视图，与「清单」视图并列，可随时切换。
- **状态必须是真的**：机器人在哪、在干嘛，只由后端任务状态推导；前端不制造进度、不为热闹假装忙。
- **决定一步可达**：门口排队、右侧面板、清单三处都能直接打开授权 / 拍板弹窗，不需要在场景里找人。
- **安静省电**：窗口不在前台暂停动画；跟随系统「减少动态效果」直接显示终态；音效默认关闭。

## 分层

| 层 | 位置 | 职责 | 依赖 |
|---|---|---|---|
| 活动推导 | `src/lib/studio/activity.ts` | 任务列表 → 每个成员当前活动（规划/开发/验证/审查/等你/空闲） | `TaskSummary` |
| 布局数据 | `src/lib/studio/layout.ts` | 房间尺寸、工位/休息点等「点位」、可行走网格（节点 + 边）、家具占地 | 无 |
| 寻路 | `src/lib/studio/path.ts` | 两个点位之间沿走道的最短路线 | 布局 |
| 分配 | `src/lib/studio/assign.ts` | 活动 → 点位；保持上一次的分配，避免机器人来回换位 | 活动、布局 |
| 渲染（后续） | `src/components/studio/` | Canvas 按深度排序画贴图；行走中的机器人参与排序，因此能被家具正确遮挡 | 贴图集 |
| 贴图集（后续） | 构建期脚本生成 PNG + JSON | 家具、机器人各朝向/姿势帧；白天、夜间两套光照 | 美术规则 |

前四层是纯函数，可单测；本轮已实现并带测试。渲染层只读这些结果，不自行判断状态。

## 数据定义（本轮已实现）

- **点位 Spot**：`id / kind / at / z / pose / node`。kind 取 `desk | plan | validate | review | queue | rest`；`node` 是它连到走道网格的入口节点。
- **走道 WalkGraph**：节点坐标加双向边。测试保证：所有节点连通；每条边都不穿过任何家具占地；每个点位都能走到。
- **活动 Activity**：每个成员取最「强」的一个：等你 > 工作中（开发/审查/验证/规划）> 空闲。映射规则与现有 `taskAvatar`、接力条一致：
  - `PLANNING` 记为开发 Agent 在规划。
  - `DEVELOPING`、`REVISING` 记为开发 Agent 在开发。
  - `VALIDATING`、`MERGING` 记为验证机在跑。
  - `REVIEWING` 记为审查 Agent 在审查。
  - `WAITING_FOR_PLAN_APPROVAL`、`BLOCKED` 记为开发 Agent 等你。
  - `WAITING_FOR_HUMAN_APPROVAL`、`MERGE_CONFLICT` 记为审查 Agent 等你。
- **分配 Placement**：成员 → 点位；工作点位满了标记 `overflow`，由面板列出，不在场景里硬塞。空闲成员按 id 稳定地挑休息点，同一个人每次去同一张沙发。

## 渲染要点（下一阶段）

1. 贴图来源：沿用 C4/C5 的生成规则：1:1 像素、统一光源、选择性描边、棱边高光、材质纹理、自发光和接触阴影。把生成脚本放进 `apps/desktop/scripts/studio-art/`，构建期输出贴图集。
2. 运行时：一个 `<canvas>`，所有家具和机器人按 `x + y` 深度排序后逐帧绘制。走动的机器人也参与排序，所以会被沙发、桌子正确遮挡，解决 C5 演示中「永远画在最上面」的问题。
3. 动画：位置补间每秒 30 帧；贴图帧每秒 6 帧；窗口隐藏时暂停。
4. 交互：点机器人打开角色卡，点排队的直接打开授权 / 拍板弹窗，点房间按阶段筛选清单。
5. 无障碍：画布外同步输出一份文字列表（谁在哪、在干嘛），读屏和键盘可用。

### 后端项目汇总 `project_summaries`（2026-11-06）

- 合同：`agentflow_contracts::ProjectSummary`，每个项目一行（没有任务的项目也有一行）：`taskCount`、`running`、`waitingForYou`、`done`、`failing`、`agents`、`activeAgents`、`lastActivityAt`。
- 分组规则与桌面首页标签一致：等你 = 等审批 / 等计划批准 / 阻塞 / 合并冲突 / 已批准待合并；完结 = 已合并 / 已回滚 / 已取消；其余算在跑。
- `failing`：近 7 天内最近一次验证结果是失败、且任务未完结的数量（读 `validation:failed` / `validation:passed` 事件）。
- `agents`：近 30 天更新过的任务里出现的开发 / 审查 Agent，去重、最近的在前；`activeAgents`：此刻在规划、开发、返工或审查的 Agent。
- 实现：`crates/orchestrator/src/project_summary.rs`（纯函数 + 5 个测试，含一个真实 SQLite 用例）；`Orchestrator::project_summaries` 只读查询；桌面命令 `project_summaries`，绑定已重新生成。
- 前端：`useProjectSummaries()`（15 秒刷新，任务变更时失效）；浏览器预览用 `src/lib/studio/projectSummary.ts` 按同一规则现算，并有对拍测试。

## 项目外观、成员与 Agent 档案接口（2026-11-06）

迁移是 `0027_studio_profiles.sql`，只新增三张表；它已登记在 persistence 的迁移指纹清单里。

| 表 | 主键 | 内容 |
|---|---|---|
| `project_appearance` | `project_id`（删项目级联） | `kind`、`roof`、`sign`、`yard_json`、`updated_at` |
| `project_members` | `(project_id, agent)`（删项目级联） | `role`（developer / reviewer / both）、`position`、`added_at` |
| `agent_profiles` | `agent`（`AgentKind` 字符串） | `nickname`、`color`、`accessory`、`catchphrase`、`updated_at` |

命令如下。读操作直接查库；写操作和项目设置一样，都经后台 daemon 执行。

- `project_appearance_list()`：每个项目一行，没存过的项目返回空值。
- `project_appearance_update({projectId, patch})`：写。
- `project_members_get({projectId})`：读。
- `project_members_set({projectId, members})`：写，整组替换，数组顺序就是 `position`；已在的成员保留原来的 `addedAt`。
- `agent_profiles_list()`：只返回自定义过的档案。
- `agent_profile_update({agent, patch})`：写。
- `agent_profile_reset({agent})`：写，删除档案并返回是否删掉了。

Patch 语义：字段不传就不改，传 `null` 就清空。昵称和口头禅传空白文字也等于清空。`yard` 传 `null` 视为不改。daemon 转发时省略不传的字段，所以 `null` 能原样到达后端。

校验规则（失败时返回 `InvalidInput`，提示是中文）：

- 颜色必须是 `#rrggbb`，存成小写。
- `kind` 只能用小写字母、数字、`-` 和 `_`，最多 32 个字符；认不出的类型原样保存，前端画成民房。
- `sign` 只能是 wood、neon、stone。
- `yard` 只能用 fountain、flag、statue、garden、bench、pet，重复的合并，最多 6 个。
- `accessory` 只能是 none、cap、headphones、glasses、bowtie、antenna、scarf。
- 昵称最多 16 个字，口头禅最多 40 个字，按字符数算。
- 成员不能重复，一个项目最多 12 个。

`ProjectSummary` 新增两个字段：

- `assignedAgents`：用户分配的成员，按摆放顺序。
- `agentsSource`：有成员时为 `assigned`，否则为 `derived`。

原有的 `agents` 不变，仍是近 30 天任务推导出的结果。前端统一用 `townAgents(summary)` 取小镇里的人数和顺序：分配过就用分配的，没分配过才退回推导结果。

### 装修和档案在像素画面上的渲染（2026-11-07）

**换色原理**：导出时把「主人选的颜色」分别画成两种灰色，对比两次的结果，找出受这个颜色影响的像素，把这些像素按 `#808080` 的灰度单独导出成「换色层」。运行时按「所选颜色 × 像素值 ÷ 灰度」逐个像素重算，明暗、描边、夜间色调都保留下来，任意颜色都能用，不需要每种颜色各导一套贴图。重算结果按（贴图块、颜色）缓存成小画布，实现在 `paintCache.ts`。

**房子**：
- `buildings.py` 新增 `MAIN` 钩子，每种房子的主色都可以替换：民房的屋顶、写字楼的点缀条、车库的锯齿屋顶、商铺的遮阳篷、工厂的屋面、天文台的穹顶条纹、图书馆的屋顶、灯塔的红色条纹。
- `town_export.py` 为每种房子、每个档位、亮和暗两种状态各导出一份 `paint` 层。
- `drawTown` 先画房子，再叠上换色层。

**院子摆件**：
- `town_yard.py` 画了 6 样：喷泉、旗杆、雕像、花圃、长椅、小狗。每样 2 帧，各有固定位置，避开小路、门牌、邮箱和原有的花坛。
- 画在房子之后、机器人之前。

**门牌**：HTML 名牌按木牌、霓虹、石碑换样式。颜色是 `theme.css` 里新增的 `--color-sign-*` 设计变量（token）。

**机器人**：
- 新增 `robot_acc.py`，在正面、背面、侧面三种朝向都能画配件：鸭舌帽、耳机、眼镜、领结、天线、围巾。看不见的朝向会跳过，比如背面不画眼镜和领结。
- `robot_layers.py` 导出两类贴图，都和机器人家族贴图共用同一个锚点，导出的姿势和帧也与家族贴图一一对应：
  - 换色层：按天线造型分，每种造型有机身和面板两层。
  - 配件层：同一个机器人戴配件和不戴配件各画一次，对比两次的结果，只留下多出来的像素。
- `drawRobot.ts` 统一绘制顺序：家族贴图 → 换色层（面板颜色由所选颜色调浅得到）→ 配件层。小屋和小镇都用它。
- `PixelBot` 新增 `color` 参数，档案弹窗里的头像会跟着所选颜色变。

**口头禅**：机器人歇着的时候，小屋气泡显示「名字 · 「口头禅」」。

**体积**：小屋和小镇的贴图共约 1.3 MB。重新出图的命令是 `python3 scripts/studio-art/export.py` 和 `python3 scripts/studio-art/town_export.py`，分别耗时约 45 秒和 20 秒。
